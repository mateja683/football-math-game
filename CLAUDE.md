# CLAUDE.md — Goal Maths

Context for continuing this project in Claude Code.

## What this is
A learning game for a 4-year-old, played with a parent: maths, reading and writing. Football theme throughout (goals, prize match), even for reading/writing. UK English throughout ("maths", en-GB speech voice). Mobile-first, portrait phone is the main target; also works on tablet and desktop.

## Architecture
Everything lives in `index.html`: inline CSS, inline JS, no framework, no build, no dependencies apart from the Google Fonts stylesheet (Baloo 2, with system fallbacks). Keep it single-file unless there's a strong reason to split.

Screens are sibling `<main class="app">` elements toggled by `show(id)`: `category` (the very first screen — the main menu: reading/writing/maths, the two-kit team bar, the grown-up prize-game button, the trophy cabinet), `teams` (the full kit grid, opened for either side), `start` (maths setup, reached from category), `play`, `end`, `prize`, `gate` (parent multiplication check), `reading`, `writing`, `wordEnd` (shared round-complete screen for reading and writing), `picker` (choose a prize game), `cabinet` (trophies).

**Every round and every prize game ends at the main menu.** `toMenu` (`() => show('category')`) is what a finished maths/reading/writing round's back button, a finished prize game's callback and the prize match's win button all lead to, and no user-facing wording says "back to maths". *Backing out* is the exception: cancelling the parent gate (`gateBack`) or the prize picker (`pickerBack`) returns to wherever it was opened from, since nothing was spent. Two full-screen overlays sit outside that list and are toggled by `show()` separately: `#pong` (the keeper/foosball game) and `#mini` (the tap-based prize games). `#timeout` is the session lock and isn't part of `show()` at all — it's toggled directly and sits above everything at `z-index:100`.

State is one object `S` (team, away, allGames, modes, voice, streak, prizes, controls, trophies, keepyBest, locked, and per-match values). `S.team` is the child's (home) kit and `S.away` the grown-up's; both are picked from the menu and both persist. `save()` persists the settings part to localStorage under the key `goalmaths`. All storage access is wrapped in try/catch — keep it that way. Maths difficulty is hardcoded via `MAX_NUM` (20) and `MIN_NUM` (3), not a user setting — there's no "numbers up to" UI any more. Reading/writing state (`RD`, `WR`) and the prize games' own state are separate and not persisted — each round always starts fresh.

### Key functions
- `make()` — builds a random question for one of the enabled modes. Sixteen of them: counting and numbers (`count`, `flash`, `more`, `bigger`, `smaller`, `oneless`, `findnum`, `next`, `ordinal`) and adding and taking away (`add`, `take`, `double`, `score`, `make10`, `make`, `share`). `bigger`/`smaller` and `make`/`make10` each share one branch. `score` is adding and taking away re-skinned as a scoreline you have to listen to rather than count, so nothing on its stage is countable; `share` and `ordinal` likewise hide the count button (`pick(activeModes())`). Returns `{mode, key, ans, text, say, win, eq?, hi?, countSel?, ...}`. Uses `MAX_NUM` as the top of the range throughout.
  - `key` prevents the same question twice in a row.
  - `hi` is the upper bound for the numeric answer buttons (defaults to `MAX_NUM`).
  - Every mode has a **floor** as well as a ceiling, built from `MIN_NUM`: "how many balls?" over two of them, or 3 + 1, is a freebie rather than a question. `bigger` also builds its pair from the smaller number up (`lo`, then `lo + 1..3`), so the two numbers are always near neighbours — telling 14 from 16 apart is the skill, not 2 from 19. `more` keeps both groups in 4–10, small enough to count as shirts and at least 2 apart.
  - `countSel` overrides which elements "Count with me" steps through.
- `awayTeam()` — the grown-up's kit. Returns `S.away`, rolling a contrasting one with `other(S.team)` the first time (or if it has somehow ended up the same as the child's) and saving it. Everything that used to call `other(S.team)` at play time — `Pong.start`, `Penalty.setup`, the `more` question — goes through this, so the away kit is a choice the pair made rather than a fresh surprise each match.
- `renderTeamBar(host)` / `openTeams(side, back)` / `chooseTeam(t)` — the home/away kit summary shown on both the menu (`#homeTeams`) and the maths screen (`#startTeams`), and the shared `teams` screen it opens. One `#teamGrid` serves both sides; `openTeams` records which side is being picked and where to return to. Picking the *other* player's kit swaps the two over, so the sides can never wear the same shirt.
- `activeModes()` — returns `ALL_MODES` when `S.allGames` is true, else `S.modes` (the manually-picked subset). Picking any individual mode chip flips `S.allGames` off.
- `next()` — renders the question: stage (balls/shirts/numbers), answer buttons, count button, speech.
- `options(ans, hi)` — the three numeric choices (answer plus near distractors, sorted ascending).
- `answer(v, el)` — right/wrong handling, streak logic (first-try-correct count for the current round).
- `goal(el)` — ball-flight animation, cheer, then next question or `endOfRound()` once `ROUND_LEN` (10) questions are done.
- `endOfRound()` / `fullTime(hits)` / `prizeUnlocked(hits, total, resume)` — a maths round is `ROUND_LEN` (10) questions. `prizeEarned(hits, total)` is the one place the unlock rule lives — perfect, or perfect but one — and all three games (maths, reading, writing) use it, so `prizeUnlocked` is shared and takes the round's own total.
- `parentGate(cb)` — grown-up-only multiplication check (factors 2–12) shown before the direct "Two-player football" button; `cb` runs on a correct answer.
- `countWithMe()`, `peek()` — hints.
- `shirt(team, label?)` — SVG shirt, optional number on it. Kits that aren't a plain colour are listed in `PATTERNED` and filled with an SVG `<pattern>` (`#kit-<team>`) that `kitDefs()` writes into the hidden `#kitDefs` at load — none are hand-written. Five kinds: `stripes` (vertical), `halves` (one tile as wide as the whole shirt so the split lands on its centre line), `band` (a centre band, `band` = its width as a fraction of the shirt, optional thin `edge` stripe either side — Ajax, PSG), `hoops` (horizontal — Sporting) and `diagonal` (accent above a line through the centre at 35°, `DIAG` — Monaco). An optional `trim` overrides the collar/cuff colour (otherwise `accent`). `patternFill()` is the single place both canvases paint those kits — Pong's `kitFill()` and `Mini.bar()` both call it — and `kitStyles()` mirrors each `kind` as a CSS gradient for the arrow buttons.
- `TEAMS` — thirty-six kits, each with a `name` (shown on screen), a `land` (the country heading it sits under in the kit grid — `LANDS` sets the heading order), an optional `say` (what the voice reads, where a name like "Man United" or "AFC Wimbledon" would otherwise be mangled — `teamSay()` falls back to `name`) and a `fam` (kit family). `other(t)` always returns a team from a *different* family, so the two sides in a prize match never look alike. The kit grid on the `teams` screen is built from `TEAMS` at load (`#teamGrid`), and the `.pbtn.<team>` arrow-button styles are generated from it too (`kitStyles()`) — neither is hand-written any more. `lightHex()`/`kitInk()` pick dark ink for the pale kits (Tottenham, Man City) so score bubbles and arrow glyphs stay readable.
- `frame(n, gone, empty)` — balls in rows of five (ten-frame layout, deliberate: helps subitising). At `MAX_NUM`=20 this can render up to 4 rows; keep an eye on this if the range ever grows further.
- `Pong` — IIFE module for the two-player canvas game, in three variants: `Pong.start(after, 'classic')` is the original keeper-vs-keeper match, `Pong.start(after, 'foosball')` is table football, `Pong.start(after, 'squad')` is three-a-side. In foosball each player has two rods that slide together on one finger: their keeper on their own goal, and a striker line of three in the *opposition* half (`pads[side].oy`, `rods()`, `drawStrikers()`). **Every bar you control knocks the ball away from your own goal**, whichever direction it arrived from, so strikers are useful going forward and no bar can ever cause an own goal. Only one bar fires per frame (`rods()` returns whether it hit, and the keeper checks are skipped if so). Rods and figures shrink with `padWEff`/`rowWEff`. The table-football look comes from `drawRod()` (metal bar across the pitch with end caps) plus `figure()` (moulded player: body, head, and for keepers a wide pair of arms matching the real blocking width); `kitFill()` keeps every kit reading correctly on bars and figures alike. Classic draws plain bars via `drawPad()` and no rods. `Pong.freeze()` cancels the animation loop without running the after-callback (used by the session lock). Bottom keeper = child's team, top keeper = `other(S.team)`. First to 3 (`WIN`), no rematch — winning always ends the session (`pback` → `stop()` → `after()`) and awards that variant's trophy. Pointer events map each touch to its half of the pitch; arrow-button mode uses the same `keys` set as the keyboard (A/D top, ←/→ bottom). **Three-a-side** (`'squad'`) is the one you *attack* in, and that is the whole point of it: Keepers and Foosball are both blocking games, so this one hands you an outfield player instead. Each side has a man on the end of a finger (`men.top` / `men.bot`), one AI team-mate (`mates`) and an AI keeper. Your man runs anywhere between the two penalty areas (`ZONE_LO`/`ZONE_HI`), *towards* your finger at a running pace rather than snapping to it (`aim()`, `moveMen()`) — teleporting onto the ball would make him unbeatable, and the run is the game. With arrow buttons there are only two per player, so they steer left and right and he closes on the ball up and down himself. Because a man can be anywhere, a touch can't be assigned by the half it lands in: `grab()` gives it to whichever free player is nearest. The AI team-mate (`moveMates()`) is penned into a strip of its own half (`m.lo/hi`) and is slower than the ball, deliberately — it helps, it isn't a wall. The keepers play themselves, and *deliberately do not track the ball*: `moveKeepers()`/`planSave()` commit to one guess per shot (`shotId`, `SAVE_P`), right or wrong, the way the penalty shootout's keeper does. This matters more than it sounds — a keeper quick enough to follow the ball saves literally everything, which is how the first version of this game ended 0-0 forever. `padW` is narrower here too, and the keeper-shrinking rally counter is switched off, since nobody is steering a keeper.

**Three things this game turns on, all found by simulating it rather than by eye — retune any of them and you have to simulate again, because every one of them was a surprise.**

1. **A man must run slower than a kicked ball** (`RUN()` is defined as a fraction of `maxSpeed()` precisely so this stays true as the pace ramps). If he doesn't, whoever is stood on the ball simply wins it straight back, both players end up glued to it and nobody can score. `KICK_LOCK` backs that up by stopping anyone but the kicker challenging until the ball has travelled.
2. **The keeper must be beatable.** The original tracking keeper gave 37 saves to 4 balls reaching the end line in 40 seconds.
3. **The ball must lose pace** (`DRAG`, floored at `ROLL` of a serve so it always keeps trundling and can never strand itself out of reach). Without drag, half of every goal was last-touched by an *AI team-mate* hoofing a clearance the full length of the pitch — the AI was still doing the work, which was the original complaint — and no keeper setting made any difference to the goal rate, because the keepers were being bypassed rather than beaten.

**Pacing is deliberately shaped, not flat.** `matchT` is seconds of actual play (roughly two thirds of the clock on the wall) and doesn't reset between goals. The ball starts at `PACE_FROM` of full speed and ramps over `RAMP`, so the opening is gentle enough for a four-year-old to follow. The keepers hold full width for `KEEP_HOLD` and then narrow to `KEEP_MIN` over `KEEP_SHRINK`: holding early stops a runaway 3-0 inside the first half-minute, narrowing afterwards stops a tight game dragging. Measured over twelve simulated matches across three standards of play, that shape puts every match between 52 and 100 seconds (median 66) — against a target of one to two minutes. Flat pacing, or first-to-4, both had matches running past 150s at one end or finishing inside 40s at the other. **Single matches are far too noisy to tune on** — a run only produces four or five goals, so measure a dozen, in parallel pages, before believing any change. `outfieldHits()` is the one place a man touches the ball: it knocks it **away from that man's own goal** at the angle it came off him, so running onto it and putting it forward is the game and no touch is ever an own goal. Your own man adds pace and re-kicks on a short cooldown (`YOU_COOL`, so he can dribble); a team-mate only nudges (`hit(cx, w, dir, gain, counts)` takes no gain and doesn't feed the rally counter) and won't grab at a ball already leaving him. `base()` and `maxSpeed()` are both lower in this variant — the ball deliberately stays slower, there's much more to watch. `drawMan()` draws all four outfield players as small 2-D footballers: a kit body, a head, arms, and legs that swing with the distance covered, with one leg thrown out and a white burst when `m.kick` is running; the man you control wears a yellow ring at his feet. The three-a-side keepers are drawn with `figure()` — the same moulded human the foosball rods use — rather than a plain bar. `askExit()` shows an in-canvas "Leave the match?" confirm on the ✕ button mid-play instead of exiting instantly. Keepers shrink (`padWEff`, floored at `MIN_PAD_SCALE`) the longer a rally stays at `maxSpeed()` without a goal, via `fullSpeedStreak` (reset in `serve()`).
- `Mini` — IIFE shell the six tap-based prize games plug into, with its own `#mini` overlay and `#mc` canvas. It owns the canvas sizing, the rAF loop, the intro message, the ✕ exit confirm and `finish(title, sub)` (which awards the trophy and shows the Done button), and hands games drawing helpers (`pitch`, `ballAt`, `netGoal`, `bar`, `text`, `dot`, `line`, `rect`, `shirtAt`, `runner`, plus `flip(fn)` to draw something turned round for the grown-up across the table and `flipX(cx, sx, fn)` to squash it sideways like a card turning over). `shirtAt` is `drawShirt()` — the canvas twin of `shirt()`, sharing its outline (`SHIRT_D`/`SLEEVE_D`) and painting patterned kits through `patternFill()`. A game is a plain object with `title`, `intro`, `setup(W,H)`, `update(dt)`, `draw()`, optional `down/move/up(x,y)` and `resize(W,H)`. **Games are held still until the intro message clears** — otherwise gravity/spawns run before the child can play. The shell only calls an optional hook when it's actually a function, so a game is free to have a plain property named `up` or `move` without the shell trying to call it.
- `Penalty` / `Keepy` / `Scramble` / `Crossbar` / `Sprint` / `Pairs` — the six `Mini` games. Penalties is a two-player shootout: `EACH` (3) shots per player, alternating, both shooting past an AI keeper that dives with `SAVE_CHANCE` ≈ ⅓. Each player shoots at the *far* goal (`shootUp` flips everything, `setShot()` rebuilds the geometry per turn) so both reach their own half of a shared screen, and a tap in the wrong half is ignored. Whose turn it is is shown in kit colours and spoken, never written. Tap-to-aim, not swipe — easier at four. Draws are allowed and celebrated. Keepy-uppies has a generous tap radius (`r * 2.6`) and a gentle centring force so the ball doesn't park against a wall; the personal best lives in `S.keepyBest`. Scramble runs `TIME` seconds with a spawn rate that ramps up; balls that get past only tick a counter, they never end the game. **Crossbar** is five shots at a yellow ring riding up and down the goal (`SWING` seconds a cycle); tap to shoot at wherever it is. The top of its swing sits only just over the bar (`hi`), so the ring is slowest right where it matters — about a fifth of every cycle is a hit, a hit window of roughly 0.3s a pass. Under the bar is still cheered as a goal, over it is "just over", never a miss. **Sprint race** is two-player: each taps their own half to run their footballer to the line, and the top lane is the bottom lane drawn through `flip()` so it faces the grown-up. The grown-up's runner needs `GROWN_TAPS` (32) to the child's `CHILD_TAPS` (20) — a deliberate handicap, since an adult taps about twice as fast; retune it if the child always loses or always wins. **Kit pairs** is memory pairs with six kits. Every kit on the board comes from a *different* `fam`, because Juventus and Partizan (or the red-and-white stripes) would be two different cards that look identical; the child's and grown-up's kits are always in it. A mismatch just turns back after a pause, with no "wrong".
- `PRIZE_GAMES` / `renderPicks(host, after, spend)` / `openPicker(after, spend)` / `usePrize(after)` / `playPrizeGame(gm)` — one list drives the picker grid, the trophy cabinet and the launching, so adding a game in one place wires up all three. `renderPicks` puts the same cards in two places: the standalone `picker` screen (for a saved prize, or the grown-up button) and inline on the `prize` screen, so a freshly won prize is one tap from playing rather than two. The prize is only spent when a game is actually chosen, so backing out of the picker costs nothing; the grown-up-gated "Prize games" button on the maths screen opens the same picker with `spend` false. `awardTrophy(key)` bumps `S.trophies[key]` and is called on *finishing* a game, not on leaving early.
- `showCabinet()` — the trophy shelf, from the category screen. Unwon games show greyed with their own icon; won ones show a trophy and a count badge.
- `lockSession()` — fires from a `setTimeout(lockSession, SESSION_LIMIT_MS)` set once at load (20 minutes). Sets `S.locked`, freezes Pong and Mini, aborts any active speech recognition, shows `#timeout`. Checked as a guard at the top of `kickoff()`, `parentGate()`, `readStart()`, `writeStart()`, and `Pong.start()`, and in the Pong keydown listener. Only cleared by reloading the page (the timer isn't persisted).
- `readStart()`/`readNext()`/`readMark(correct)` — reading game (screen `reading`, state `RD`). Shows a word from `READ_BANKS` (3–4 letters). It picks the **length first, then the word** (`pick(pick(READ_BANKS))`) — `WORDS3` is nearly four times the size of `WORDS4`, so picking flat from `READ_WORDS` would leave the reading game mostly three-letter words. An even split is what it was in practice back when the two banks were the same size. The word is shown in large print — deliberately **not** spoken aloud, unlike maths questions, since the whole point is the child decoding it themselves. `recognizer` (Web Speech API, feature-detected from `SpeechRecognition`/`webkitSpeechRecognition`) drives a hold-to-listen 🎤 button (`pointerdown` → `recognizer.start()`, release → `recognizer.stop()`) that's the only control shown by default when supported. It only ever auto-*confirms* a correct read; a mismatch just invites another hold, never marks it wrong. `#readAskGrownup` is a small always-present link that reveals the manual `#readRight`/`#readAgain` buttons (`#readJudge`) for that word if the mic keeps struggling; it resets to mic-only on the next word. When `recognizer` is unavailable, the mic/link are hidden and `#readJudge` shows directly instead — that's the sole fallback path in that case.
- `writeStart()`/`writeNext()`/`writeMark(correct)` — writing game (screen `writing`, state `WR`). Shows a picture (`WRITE_WORDS` is `WORDS3` only — **three letters max**, because writing a word by hand is far harder at four than reading one) with the word hidden until "Show hint"; the child writes on the `#wc` canvas (plain pointer-event freehand drawing, Apple Pencil/touch/mouse all work via Pointer Events same as `Pong`).   The pad is the whole white box: `#wc` is `position:absolute;inset:0` inside `.canvasbox`, **not** `height:100%` — `.canvasbox` is a flex item with no definite height, so a percentage height never resolved and the canvas used to collapse to its 2:1 intrinsic ratio, covering only the top ~45% of the white area and leaving the rest dead to the touch. `wDims()` only rebuilds the bitmap when the box has actually changed size and copies the existing drawing across, and a `ResizeObserver` on `#wc` runs it whenever the box moves (the web font loading, the address bar collapsing, rotation) — otherwise the bitmap and the box drift apart and the strokes land in the wrong place. The "Show hint" word (`.hintword`) is absolutely positioned *over* the pad rather than above it, so revealing it can't resize the canvas, and the child can copy it where they're writing. There's no handwriting OCR — a backend or ML model would be needed for that and would contradict the single-file/no-dependencies architecture, and wouldn't be reliable for a young child's handwriting anyway — so `#writeRight`/`#writeAgain` (parent-judged) is the only marking mechanism, matching the app's "played with a parent" design.
- `wordRoundDone(kind, hits, replay)` / `wordEnd(kind, hits, replay)` — shared round end for both reading and writing (`WORD_ROUND` = 8 words/round); `replay` is `readStart` or `writeStart` depending which just finished. `wordRoundDone` awards the prize match via `prizeEarned` exactly like maths does, so 8/8 or 7/8 unlocks it. `RD.hits`/`WR.hits` count words got right *without* a "Try again" first (`RD.missed`/`WR.missed`, reset per word). A mic mismatch in the reading game deliberately does **not** set `missed` — only an explicit grown-up "Try again" tap does — so a misheard correct answer never costs the child their prize. Using the writing "Show hint" doesn't count against them either.
- Sound: `speak()` (speechSynthesis), `whistle()`, `cheer()`, `thud()`, `ping()` (the crossbar) (Web Audio, no audio files).

### Adding things
- **New question type:** add a branch in `make()`, a render branch in `next()`, a chip with `class="chip mode" data-mode="..."` inside the right group of `#modePicker` on the start screen, and a gentle wrong-answer line in `answer()`. Anything tappable on the stage just needs a `data-v` — `next()` binds by that attribute, not by class, so a panel that isn't a button (the `score` scoreboard) stays inert. It's automatically included when "All games" is on since that reads from `ALL_MODES` — add it there too.
- **New team:** add an entry to `TEAMS` (`name`, `land`, `fam`, `main`, `trim`, `confetti`, and `say` if the name doesn't read aloud well) — that's all: the `teams` grid button and the `.pbtn.<team>` style are both generated from it. Give it a `fam` that groups it with any kit it could be confused with, so `other()` never puts the two of them on the same pitch. Club names as labels are fine (the owner asked for them), but the kit itself is still **colours only** — never draw a crest, badge, mascot or club logo. If the kit isn't a plain colour, add it to `PATTERNED` (any existing `kind`, like `red`/`halves`/`ajax`) or `SLEEVED` (contrast sleeve panels, like `claret`/`amber`) instead of special-casing `shirt()`/`drawPad()` directly — both are already generic over those two lists. A genuinely new look means a new `kind` in `PATTERNED`, taught to `patternFill()`, `kitStyles()` and `kitDefs()`; that's three places and no more. A new country also needs adding to `LANDS`, or its kits won't appear in the grid.
- **New reading/writing words:** add `{w, e}` (word, emoji) to `WORDS3`/`WORDS4`. Reading draws from both (an even split by length, see `READ_BANKS`); writing draws from `WORDS3` alone, which is why that bank is by far the biggest (54 words). `WORDS5` is kept but nothing currently draws on it. Keep emoji unambiguous — it's the only "picture" support, no image assets, and in the writing game the picture is the **entire** prompt. That's the real limit on how big `WORDS3` can get: there's no way to draw "the", "did" or "was", so a 200-word phonics list doesn't translate. Prefer a concrete noun with one obvious emoji, and check the emoji isn't already carrying another word.
- **New prize game:** write a `Mini` game object (see `Keepy` for the simplest one) and add a row to `PRIZE_GAMES`; the picker, the launcher and the trophy cabinet all read from that list. Only reach for a new overlay if the game genuinely can't live on `Mini`'s canvas — foosball sits inside `Pong` rather than `Mini` precisely because it reuses that game's physics, controls and exit handling.

## Design rules to keep
- Wrong answers are never punished: the button wobbles and fades, and a kind voice line plays. No opponent goals, no in-question timers (the session limit is a screen-time guard, not gameplay pressure — it never counts down visibly or rushes an answer). Speech recognition in the reading game follows the same rule: a mismatch never marks the child wrong, it only asks the grown-up to check.
- Maths questions are always read aloud (child can't read yet); 🔊 repeats. Reading-game words are the deliberate exception — never auto-spoken, since reading them is the point.
- Big tap targets, sentence case, minimal text.
- Respect `prefers-reduced-motion` (animations are skipped; see the `reduced` flag).
- Kits are **drawn** as colours only: never a real club crest, badge, mascot or logo, whatever is asked for. Club *names* as labels are fine and deliberate — every kit carries one, because the child knows the teams by name and several kits are close in colour. Millwall is drawn with white sleeves rather than plain royal blue, on purpose: it keeps it apart from Everton and Chelsea at shirt-icon size.
- Safe-area insets are handled for phones with notches.

## Ideas discussed but not built
- A more forgiving streak (a miss knocks off a couple of bars instead of resetting to zero).
- A configurable "numbers up to" level again (currently hardcoded to `MAX_NUM = 20`).
- Difficulty levels / word-length picker for reading and writing (currently a fixed 3–4 letter pool for reading and 3 letters for writing, no way to change either).
- True handwriting recognition for the writing game (would need a backend/ML model — see `writeMark` above for why that's out of scope here).

## Testing
There are no automated tests. Before committing, at minimum:
- syntax-check the script: `node -e "const h=require('fs').readFileSync('index.html','utf8');new Function(h.split('<script>')[1].split('</script>')[0])"`
- open it on a real phone and try each game mode, a full match, and each prize-match variant (keepers, foosball, three-a-side) in both control modes with two players.
